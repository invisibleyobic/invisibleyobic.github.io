Локальный редакционный конвейер ОЗОТЭНС работает на Node.js 22+ без npm-зависимостей. Он готовит задания, структурированные черновики, карты подтверждений и HTML в структуре `articles/<slug>/index.html`. Шаблон берётся из текущей главной ОЗОТЭНС, включая общие навигацию, стили и скрипты навигации и корзины. Сборка создаёт новый файл в staging. Файлы сайта, индекс статей и поисковый индекс командами конвейера не изменяются.

Исходный «Статейник» v1.0.0 изучен из архива пользователя. Его стек — Next.js 14, React 18, Prisma 5 и PostgreSQL. Админка, авторизация, аналитика, расписание и полнотекстовый поиск требуют работающего Node-сервера и базы. GitHub Pages обслуживает статические файлы. Для текущего сайта выбран отдельный локальный конвейер с экспортом HTML. Исходный платный архив, персональная ссылка на скачивание и лицензионные данные в этот каталог не скопированы.

Из авторских материалов использованы принципы промптов «Вопросы для статьи», «Подключить отдельного судью» и «Самопроверка по спеке». Сначала формулируется вопрос читателя, затем источники и пробелы, после — независимая проверка результата. Эти материалы прочитаны как пользовательские данные.

Запустите проверку реализации из корня репозитория.

```powershell
node --test tools/ozotens-editorial/editorial.test.mjs
```

Подготовьте задание. Эта команда создаёт JSON с медицинской проверкой по умолчанию. Источники выбираются по ID из `sources.json`.

```powershell
node tools/ozotens-editorial/editorial.mjs prepare topic-slug --title "Название темы" --question "Какой конкретный вопрос читателя раскрываем?" --sources medozons-device
node tools/ozotens-editorial/editorial.mjs packet tools/ozotens-editorial/drafts/topic-slug.json
```

Для обычной темы вне медицинского содержания можно явно передать `--medical false`. Медицинские утверждения требуют первичных источников, проверенных тезисов и отдельного профильного проверяющего. Автоматическая проверка структуры не устанавливает истинность утверждений и квалификацию человека. Это подтверждается содержательной проверкой редактора и специалиста.

Для тем из общего редакционного индекса предусмотрен мост метаданных. Он забирает тему и вопрос, сохраняя существующие статьи без изменений. Источники для будущей генерации выбираются из отдельного проверенного реестра.

```powershell
node tools/ozotens-editorial/editorial.mjs prepare-topic ozonebox-review/ozotens/editorial-data.json --slug topic-slug --sources medozons-device --out tools/ozotens-editorial/drafts/topic-slug.json
```

В `editorial-data.json` ожидается объект с массивом `articles`, у элементов нужны `slug`, `title` и `question` либо `description`. Схема статей сайта с `sections[].paragraphs` как массивом строк допускается на входе моста, поскольку импортируются только метаданные. Содержимое существующих статей не получает автоматически статус медицинского утверждения.

Автоматическое написание подключается отдельно через OpenRouter. Нужен API-ключ, оплаченный доступ и явно выбранная модель с поддержкой строгого JSON Schema. API соответствует официальному Chat Completions API. [Документация OpenRouter](https://openrouter.ai/docs/api_reference/overview), [структурированные ответы](https://openrouter.ai/docs/guides/features/structured-outputs).

Скопируйте `.env.example` в `.env` внутри этого каталога и заполните локально. Для PDF-источников укажите Python с установленным `pypdf`. Для HTML-источника достаточно Node.js. Ключ передаётся только фиксированному адресу OpenRouter. В запрос модели отправляются вопрос и извлечённые тексты выбранных документов.

```powershell
node --env-file=tools/ozotens-editorial/.env tools/ozotens-editorial/editorial.mjs generate tools/ozotens-editorial/drafts/topic-slug.json --out tools/ozotens-editorial/drafts/topic-slug-generated.json
```

Генератор загружает только точные первичные URL из `sources.json`. Перенаправления отклоняются, лимит ответа одного источника — 8 МБ, извлечённый текст ограничен 24 000 символами, источников может быть от одного до шести. Снимки текста, даты и SHA-256 сохраняются в черновике. При усечении текста выставляется `truncated`. Обработка PDF может потребовать отдельного разбиения документа редактором, если нужная страница не попала в извлечённый фрагмент. Новые ссылки из ответа модели не принимаются. Модель не может выставить подписи проверяющих или одобрение публикации. Повторные автоматические попытки после платного API-запроса отсутствуют, чтобы случайно не удвоить расход.

Без API можно автоматически собрать черновик из подготовленных фактов. Внешний JSON фактов содержит массив объектов `heading`, `text`, `sourceIds`, `evidence`. Для evidence нужны `sourceId`, `locator`, `notes`, `checkedBy` и `checkedAt` в формате YYYY-MM-DD. Это входной материал автора, который ещё проходит редакционный контроль.

```powershell
node tools/ozotens-editorial/editorial.mjs import-facts tools/ozotens-editorial/drafts/topic-slug.json --facts facts.json --out tools/ozotens-editorial/drafts/topic-slug-facts.json
node tools/ozotens-editorial/editorial.mjs check tools/ozotens-editorial/drafts/topic-slug-facts.json
```

Полная схема черновика версии 1 задаётся следующими полями.

- `slug`, `title`, `description`, `question`, `medical`.
- `sources` с `id`, `title`, `url`, `primary`, `type` и необязательным `scope`.
- `claims` с `id`, `text`, `sourceIds` и `evidence`.
- `sections` с `heading` и `paragraphs`, где каждый абзац содержит `text` и `claimIds`.
- `authorNotes` с нерешёнными вопросами и `reviews` с отдельными результатами проверок.

Фактчекер заполняет `checkedBy`, дату и содержательную заметку после чтения источника. Для медицинского абзаца обязателен известный тезис с первичным источником. Локатор обозначает страницу, раздел или таблицу документа. Редактор проверяет соответствие абзаца источнику, ограничения выборки и применимость к описанной модели. Указание `primary: true` в реестре означает тип источника и само по себе не подтверждает рекламное обещание.

Проверяющие записывают решения отдельными командами. Новая ревизия сохраняется в новый файл. Для медицинского материала имена редактора и профильного специалиста должны различаться.

```powershell
node tools/ozotens-editorial/editorial.mjs review draft-factchecked.json --role editor --reviewer "Имя редактора" --decision approved --notes "Что и по каким источникам проверено" --out draft-editor-reviewed.json
node tools/ozotens-editorial/editorial.mjs review draft-editor-reviewed.json --role medical --reviewer "Имя врача" --qualification "Специальность и роль" --decision approved --notes "Проверены утверждения, ограничения и инструкции" --out draft-reviewed.json
node tools/ozotens-editorial/editorial.mjs check draft-reviewed.json --publication true
node tools/ozotens-editorial/editorial.mjs build draft-reviewed.json
```

Вариант решения `changes-required` фиксирует необходимость правки. Решения привязаны к SHA-256 содержимого, тезисов, источников и снимков. Любое изменение содержимого аннулирует старое одобрение. Все команды сохраняют новый файл исключительно, без перезаписи существующей ревизии. Полученный HTML экранирует текст автора, не исполняет MDX и не встраивает произвольный HTML. В нём есть ссылки на источники, canonical и Article JSON-LD.

Результат build по умолчанию находится в `tools/ozotens-editorial/staging/articles/<slug>/index.html`. Параметр `--out` меняет корень выходного дерева, `--site` задаёт каталог сайта для чтения оболочки. Новую статью следует открыть в локальном просмотре с ресурсами сайта. После проверки человек переносит HTML в рабочую структуру, обновляет общий редакционный индекс и запускает существующий `tools/build_ozotens_index.py`. Публикация остаётся обычной процедурой репозитория. Конвейер не делает git commit, push, деплой и обновление индекса.

Запуск по расписанию возможен на постоянно включённом компьютере, VPS или GitHub Actions. Расписание должно запускать только `prepare-topic` и `generate`, сохранять новый JSON как закрытый артефакт и уведомлять редактора обычным рабочим способом. Ключ хранится в секретах среды запуска, а не на GitHub Pages. Cron не должен вызывать публикацию. При параллельных запусках задавайте уникальный путь результата с датой и ID запуска, одинаковое имя завершится ошибкой без замены файла.

На момент добавления выполнены локальные тесты проверки источников, запрета публикации без одобрения, аннулирования одобрения после правок, экранирования HTML, сохранения текущего сайта, ограничения ответа, отбрасывания выдуманных ссылок и работы CLI. Сетевой OpenRouter-запрос не выполнялся, расходования средств не было. Для настоящей генерации остаются настройка ключа и модели, доступ к первичным страницам и последующий содержательный фактчек.

### Передача одобренной статьи в библиотеку сайта

Подготовка инструмента завершена: `prepared: true`. Полная автоматическая публикация не включена: `autopublish: false`. `prepare-topic` и `build` не изменяют библиотеку. Само копирование staging HTML не добавляет карточку в общий индекс.

1. Сохраните проверенный JSON и результат `check --publication true`. Соберите staging HTML и проверьте страницу с текущими ресурсами сайта.
2. В `ozonebox-review/ozotens/editorial-data.json` добавьте или обновите один объект `articles` по уникальному `slug`, сохраняя остальные статьи и `categories`. Заполните существующий `category`, реальные `cover` и `coverAlt`, `keywords`, `question`, `description`, `lead`, `questions`, `related`, `words`, `readingMinutes` и `updatedAt`. Не придумывайте иллюстрацию или связанную статью.
3. Преобразуйте абзацы черновика `{text, claimIds}` в строки `text` внутри `sections[].paragraphs`. Секции получают уникальный `id`, `heading` и `sourceIds`: объединение источников тезисов из её `claimIds`. Сохраните исходные `sources` с `id`, `title`, точным `url`, `primary`, `type`. Фактчек, снимки и подписанные reviews остаются в редакционном JSON: библиотечная схема не заменяет этот журнал.
4. Перенесите проверенный HTML в `articles/<slug>/index.html` либо используйте поддерживаемый генератор страниц библиотеки из общего JSON. Убедитесь, что новый slug не перезаписывает другую тему. Публичный текст и карточка должны соответствовать одобренной ревизии.
5. Выполните существующий `tools/build_ozotens_index.py` из корня репозитория через установленный Python. Он обновляет поиск, sitemap и canonical по реально созданным HTML; он не преобразует editorial-data в статьи. Проверьте карточку, источники, мобильную страницу и поиск. Публикацию репозитория отдельно выполняет владелец сайта.

Реестр дополнен источниками текущих 20 статей: WHO/NICE/NIAMS/NHS, официальными AAOS/HSE и указанным систематическим обзором. Стабильные ID сохранены, повторяющихся URL нет. Тип источника сохраняется: обзор не обозначается новым клиническим испытанием. Это allowlist, а не обещание доступности: выбранные страницы загружаются при запуске, перенаправления отклоняются. Для нового адреса вручную проверьте владельца и актуальный URL, затем обновите реестр. Общая рекомендация не является доказательством эффективности конкретного комплекта ОЗОТЭНС.
